# 2026-10-26 H3失败排查与修复

## 已核实的故障

10月25日三次Turbo8任务均在采样阶段由监督进程触及82℃停止，进度分别为7/8、6/8和7/8。描述编码已完成。原监督进程保存了超温异常，但随后终止两rank的清理异常覆盖了rank报告，页面因此只看到泛化的“视频采样未完成”。这些失败不能记为完整成片，也没有调用收费API。

本轮优先读取每个任务自己的 `supervisor-failure.json`，保留原私有日志与失败状态，仅纠正三条已证实失败记录的用户提示。界面实际查看通过：明确显示“82℃紧急停止线”，不暴露私有路径。

## 本轮改动

- 保留8步、Euler、LoRA一次预合并、同视频双卡和82℃紧急停止。
- 温度目标仍约80℃，以77℃开始降温、74℃恢复，留出单个计算块升温余量。没有改风扇、功耗或驱动。
- 两rank完成CUDA工作后先在CPU/Gloo会合，再读温度；监督检查周期由5秒缩至1秒，失败记录保留当时双卡读数。
- 原始数值模型profile标识保留以兼容已验收LoRA/采样合同；实际热控策略与执行器SHA在新阶段报告独立记录。不能把旧标识中的历史温度字样当作当前策略。

19项CPU针对性检查通过（9.638秒），覆盖根因优先级、损坏报告回退、提示脱敏、8步合同、资源准入和解码恢复等。在线更新前确认无排队或运行任务，短暂维护和全局锁保护下备份部署；API与两个worker未重启。
