# 给技术审阅者的阅读路线

项目用FastAPI、SQLite和原生HTML/CSS/JavaScript实现视频任务平台。模型在独立进程执行，API先保存任务并返回ID，浏览器查询进度和受权限保护的媒体。当前是单机单协调器，H3用两张卡共同采样同一条视频；不将HTTP并发接入等同GPU吞吐。

## 从一次请求看实现

| 需要检查的行为 | 阅读入口 | 可以复查的约束 |
| --- | --- | --- |
| 提交、查询与下载 | `video_platform/api.py` | 严格输入、会话身份、CSRF、状态码、媒体Range |
| 同账号重复点击 | `video_platform/store.py` | 幂等标识结合owner与参数，同key不同参数冲突 |
| 两个账号相同描述 | `ownership.py`、`auth.py`、数据层owner过滤 | 提示词不充当共享文件名，任务目录按ID分开 |
| 多请求同时领取 | `store.py`、`worker.py` | 短事务claim、单协调器、有限排队与背压 |
| 模型进程和GPU | `worker.py`、`h3_local.py`、`h3_runtime.py` | 全局/卡锁、实际占用检查、配置版本、阶段交接与故障报告 |
| 作品形成一集 | `projects.py`、`composition.py` | 剧集/分镜版本、选片、revision冲突、素材不足拒绝导出 |
| 管理操作 | `management.py` | 服务端角色检查、真实数据库统计与操作审计；未接支付 |
| 需求助手 | `agent.py` | 本地有界工具链；外部语言文案API已移除 |

表中未写目录前缀的Python文件均在`video_platform/`。先读[架构](ARCHITECTURE.md)再沿这些入口追踪，比逐文件翻阅更容易判断职责。

## 不下载模型也能检查什么

按主README在Linux/WSL创建独立环境后运行完整CPU测试及Node规则测试，或者按FRIEND_README启动CPU审阅配置。公开副本已有126项CPU通过；后续新增耗时说明后的20项前端规则通过。新主机依赖安装、重新构建Docker及GitHub托管CI尚未重新验收，不将已有服务器测试等同于这些结果。

CPU审阅实例使用独立空数据库，支持账号、项目和管理流程；生成、外部语言调用及视频导出由服务端禁用。静态`preview/`播放的是此前生成的真实作品，H3雨夜样例来自历史官方API。它不会连接作者实验室，也不是朋友远程推理服务。

## 真实生成验证与限制

作者环境的Wan、CogVideoX和H3有真实记录；CogVideoX曾出现白屏失败，当前仍是实验预览。H3两卡同视频已完成独立成片，并通过普通账号公网新提交、状态查询、Range206与下载SHA验证。新H3视频约5.17秒，生成约48.8分钟，主要等待降温，不能当成低延迟产品或双卡提速基准。

浏览器工具对新公网标签读取超时，因此最新H3的浏览器播放到结尾未完成；朋友本人网络也未实测。早期其他样例的浏览器验证属于各自记录，不能替代这条新任务。细节见[实际验证](VALIDATION.md)。

本地H3依赖固定兼容环境和独立runner，通用可移植安装器尚未整理完毕。缺少runtime或对应真实验收标记时拒绝生成，不静默调用商业API。自带密钥的四家语言接口仅完成模拟验证，默认关闭，不能说全部提供商已接通。

## 希望得到的技术反馈

重点检查账号到文件的权限链、幂等与任务状态转换、崩溃恢复的歧义、单机SQLite的容量边界、推理环境复现和成本/耗时提示。正式公开服务仍缺少独立生产资源、针对性容量验收、内容治理、监控告警和异机恢复；CPU隔离恢复已做，不冒充GPU环境灾备。

本项目由开发者借助Codex实施。目标是能够亲自解释一条请求、复现一个测试和定位一次失败；不以生成的代码量或模型名称代替能力证明。
